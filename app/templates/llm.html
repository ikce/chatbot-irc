Throttle

Le bot ne répondra pas si l'un des 2 timers n'est pas expiré.

Web search — kill-switch global

C'est un kill-switch. L'injection réelle dans le payload requiert en plus que chaque user ait 🌐 Web search coché dans /users. Effectif = (kill-switch ON) ET (opt-in per-user ON). OpenWebUI enrichit lui-même le contexte avant l'appel au modèle — aucun appel HTTP séparé côté bot.

Tools Open WebUI (lecture des liens)

Envoyés en tool_ids à Open WebUI quand un message adressé au bot contient un lien et que son auteur a URL fetch coché dans /users (admins compris). Pas pour les réponses spontanées ni les au revoir. Vide = désactivé. Ex. web_fetch pour le tool « Web Fetch + Vision ».

Query intent (accès DB modération)

Flux 2-tours : (1) extraction d'intent JSON, (2) query DB, (3) reformulation via la persona. Fallback silencieux sur le chat classique si l'intent est chat ou si l'extraction échoue. Requêtes possibles : IP d'un nick, nicks d'une IP/host, first/last seen, stats bans/flags, top hosts.

Mémoire long terme

Comparé sans majuscules ni accents ; /regex/ pour une expression régulière. Un fait qui matche est refusé, qu'il vienne de !mem add/pub/about ou de l'extraction automatique. Les faits déjà retenus ne sont pas effacés. Identité : compte NickServ > ident@host > nick + même FAI/ident. Un nick seul sur une connexion inconnue n'a accès qu'aux faits publics et n'écrit rien. Faits appris en PV = privés (jamais injectés en channel). L'extraction se fait aussi après 5 min de silence. Côté users : !mem list|forget|off|who en PV.

Réponses spontanées

Dans ces channels, le bot peut répondre sans être mentionné : quand quelqu'un continue une conversation avec lui (3 min), ou quand une question est posée au channel (au plus une fois par délai ci-dessus). Un petit modèle « juge » décide à chaque fois, et chaque décision s'affiche dans la console ([auto]). Seuls les users avec 💬 LLM chat sont concernés ; le throttle habituel s'applique aussi.
Quand quelqu'un annonce qu'il part (« bonne nuit », « j'y vais », « a+ »…), le bot lui dit au revoir sans être mentionné. Le modèle juge confirme d'abord que c'est vraiment un départ (console : [bye]). Marche pour tout le monde, une fois par personne et par channel toutes les 30 min.
Le bot ignore quelqu'un pendant cette durée s'il pose 3 fois la même question en 10 min, ou si le LLM juge qu'il insiste après un refus (il termine alors sa réponse par [IGNORE], retiré avant envoi). Nick et ident@host sont ignorés tous les deux. Admins jamais ignorés ; !unignore <nick> pour lever. Un redémarrage du bot lève tous les ignores.

Aperçu des liens

Variables : {title} {site} {description} {domain} {url}, et pour YouTube {channel} {duration} {views} {likes} {date}. Un bloc [[ … ]] ne s'affiche que si ses variables sont remplies, par ex. [[ — {site}]]. Ligne titre vide = rien de posté pour ce type de lien. Qui déclenche l'aperçu : le flag 🔗 URL fetch dans /users, admins compris. Les changements s'appliquent tout de suite, même aux liens en cache.

Triggers migrés vers /users

La table de triggers séparée n'existe plus. Chaque user porte désormais son propre keyword (vide = mention du nick du bot ou PV) directement dans la page /users, à côté de la checkbox 💬 LLM chat. Un user sans 💬 LLM chat ne déclenchera jamais le bot, même si son keyword matche.
